# Changelog

## Unreleased

- **A reply read on one client is read on all.** The window keeps the read state: while any tab of it is visible and focused, its replies count as read, so the switcher and Inbox badges, a paired computer's list and the favicon's done dot agree everywhere. The phone keeps its own unread count for now.
- **The draft is shared, per session.** What you are writing and its attached images show in every tab of the window and on a paired computer, survive a reload, a restart and an update, and each session keeps its own: switch away and back and it is still there. The last edit wins, and a send from anywhere clears it. The phone keeps its own draft for now.
- **A window is live on every client at once, with no Work here.** Browser tabs, the phone and a paired computer's tab all show the window and act in it together; none is parked behind "already open in another tab". When two answer one question, the first counts and the other hears it was already answered. A page that meets an older server says to restart the server.

## 2.3.0 — 2026-11-26

- **Message fields show markdown as you type.** The chat's field and the comment popup draw bold, italics, strikethrough, code, links, lists, quotes and code blocks while you write and still send the markdown itself; a mark hides once the caret leaves it. ` ``` ` opens a code block with the caret inside, as in Slack.
- **Lists nest with Tab, and a format bar.** Tab and Shift+Tab nest and un-nest a list item or indent a code line; nested numbers go 1., a., i. A selection gets a bar: bold, italic, strikethrough, code, link, code block, lists and quote, with Mod-B, Mod-I, Mod-Shift-X, Mod-E and Mod-K. An open `**`, `*`, `_`, `~~` or `` ` `` formats what follows it.
- **Media markup: a lasso and a Select tool.** The Mask tool draws a free outline by dragging (it keeps only the points its shape needs) or one point per click, close together. **Select (V)** picks any shape to move it, drag its corners, ends or points, bow a mask's side into a curve, or delete a point or the whole shape with Delete.
- **A project opens from the page at once.** **Open folder…**, **New project…** and Recent no longer start a launcher process to open the folder: the server opens it itself.
- **`nota-bene` with no folder opens the home page.** A start of the app is its home page, where you open a project: of the running Nota Bene, or of a new one with no agent yet. The app icon opens it too (it opened the most recent project). `nota-bene <folder>` opens that project as before; for the current folder it is now `nota-bene .`, and `--resume`, `--new` and `--continue` need a folder.
- **Settings has no Windows section.** The project switcher and the home page list every agent, open and close it; a server is restarted from its own page (▾ next to ↻ Agent).
- **A session open in another agent is not deleted.** With several agents, on one server or on several, the session list let you delete a conversation another agent had open; the branch list also did not mark a folder whose agent was at work, and let its branch be switched.
- **Usage limits are recorded for every Claude agent.** Only the agent the server was started with recorded them, and after a server restart none did; the limits chart then had gaps.
- **An agent with a background task running shows as working.** The project switcher, the home page and the phone listed it as idle once its turn ended, though a subagent or a shell still ran; a watcher alone (Monitor) still does not count.
- **Phone: the model changes again with a long list of models.** The model sheet's list scrolls; the effort and **Apply** stay on screen, where before they fell below its edge and a pick was never sent.
- **A long Claude conversation opens at once.** Its history is read from the last compaction, not from the whole transcript: one of 2.1 GB now opens in a few milliseconds instead of minutes.
- **A huge conversation no longer freezes the window.** Opening a Claude session whose transcript is past 512 MiB used to hang the server and every agent in it; now its history is not shown, the page says why, and the agent continues the conversation as usual.
- **A model picked for one agent stays with it.** The model chosen for a folder is kept per agent: Claude no longer starts with a model picked for Codex on the same folder (its /compact then failed). A choice made before this update is forgotten once: pick it again.
- **A project image or video in a chat opens in its own tab again.** On an agent's page (`/a/<id>/`) a markdown image no longer opened its file tab, and a chat video had no player of ours.
- **Phone: Send beside the microphone while comments wait.** Pending comments go with Send alone, from the chat's empty field; the microphone still records, and the recording takes them along.
- **The home page runs the swarm.** It keeps the app's frame: a Projects panel with each project's agents and sessions, and an Inbox that puts first the agents waiting for you and answers their requests in place. **Home** in the rail leads back to it.
- **A home page for the server.** Its own address lists the projects (running, Recent) and opens or makes one, with no agent of its own. Closing the server's last agent goes there; the server stays up, and the phone no longer lists it.
- **One window, one agent.** A page shows one agent: **✕** in the chat's tab closes it and goes to the server's home; a page whose agent was closed elsewhere moves to another agent instead of reconnecting forever. To work on a project in parallel, open another worktree of it, in its own window.
- **Phone: projects open again after the update to one Nota Bene for every folder.** A connector started before it is replaced, so tabs no longer wait for the window; a server whose folder's agent was closed is listed under the agent it shows.
- **The chat's tab shows its agent's mark.** Claude's, OpenAI's (Codex) or omp's.
- **A server's first agent closes like the others.** Its row in the switcher closes it alone while another agent of the server is open; the server and the other agents go on.
- **Phone: a project's agents together.** The phone keeps a folder's agents next to each other.
- **The switcher lists a project's agents** and closes one.
- **Another computer's agents in the switcher.** The projects a paired computer's Nota Bene holds are listed and open from here, each agent by itself.
- **A restart no longer loses a subagent's report.** A background task that just ended is reported a few seconds later; a pending restart now waits for that report.
- **One Nota Bene for every folder.** With Nota Bene running, `nota-bene`, `/nb` and the project starter open another folder in it, under `/a/<agent>/` on the same port, instead of starting a window per folder; any agent, several folders. An open Nota Bene tab on this computer moves to that folder instead of a new tab opening. Each is a row of the switcher and a tile of the rail, with its state and badge; Stop on its row closes it alone, the rest go on. A window whose server holds other folders has no Stop on its row: **Stop Nota Bene** ends them all. Those folders come back after a restart, a crash or an update. `/nb` no longer runs Nota Bene as a background task of the Claude Code session: it keeps running after the session ends, until **Stop Nota Bene** (⏻). A window of its own beside it (one started while another was starting, or from now on updated in place) hands its folder to the server below it once it has no tab and nothing under way for about a minute, then ends; its session goes on there. Windows started by an earlier release do not: stop them and open their folders again. `--port N` still starts a server of its own, which never does.
- **A pending server restart no longer stalls every project.** While one project works, the others keep sending and compacting; only the project the restart waits for holds its messages.
- **Phone: the projects of one server.** Folders opened in a running Nota Bene (its other agents) are listed on the phone again and open there; before, it showed only the server's first project. A phone app before this release still shows only that one.
- **An app icon.** `nota-bene shortcut` adds Nota Bene to your apps (macOS `~/Applications`, the Windows Start menu, a Linux `.desktop` file); a click opens your most recent project, starting Nota Bene if needed. Until it is there, a tab on this computer offers it in a notification: **Add** or **Not now** (30 days). Also `nota-bene --app`.
- **Phone: a readable notification icon.** The status bar showed Nota Bene's notifications as a dot; it now shows the speech bubble.
- **Remote access: an outdated connector is replaced after an update from a checkout.** A window replaced the shared connector only when the package version was older, and a checkout keeps its version between releases, so after pulling a window kept a connector started on older code (with one from before 2.2.0, another computer's windows did not appear). Now a connector speaking an older protocol is replaced as well.

## 2.2.0 — 2026-11-21

- **Remote access: work in another computer's projects.** With a computer paired (Remote tab, **Connect to a computer**), the project switcher and the rail list its running windows beside this computer's, with a laptop on the tile and its name; choosing one opens it in the same tab with the full interface, end-to-end encrypted through the relay, and the switcher there moves back to either computer. Its page offers no Open folder, New project, Recent, stop, Show in Finder or Remote tab, and refuses files over 32 MB before sending them. Both computers need this release. See [Working in another computer's projects](https://github.com/iCubeDm/nota-bene-ide/blob/main/docs/guide.md#working-in-another-computers-projects).
- **Remote access: connect to another computer (first step).** The Remote tab's **Pair a phone** is now **Pair a device**, and a new **Connect to a computer** takes the code another computer shows there: this computer pairs with it as a device (its own key, `remote/device.key`), lists it as online, connecting, not reachable or revoked, and can **Forget** it; it needs no relay or access key of its own. The other computer lists it among its devices and can revoke it. Also `nota-bene remote connect`, `computers` and `forget`.
- **Remote access: a computer no longer pairs with itself.** **Connect to a computer** (and `nota-bene remote connect`) refuses this computer's own code from *Pair a device* and says to paste it on the other computer.
- **Remote access: refusals in your language.** The Remote tab says why a pairing code, relay address or access key was refused (and that the connector is not running or is an older version) in the interface language; before, it showed the server's English text. The CLI's messages are unchanged.
- **Compact while the agent works.** Compact (the button, the phone's, or a typed `/compact`, instructions kept) no longer says the agent is busy: it waits for the agent's next pause, also with no page open, and every tab and the phone show **Compact pending** with **Cancel**. A pending server restart goes first. Messages sent after a restart or a compaction was ordered wait (dimmed in the chat) and go after them, in order; they survive the restart. Before, a message sent while a restart was pending was answered before the restart. **Send now** still interrupts at once, and an older phone app's messages are still answered first; `/clear` is refused while the agent works or a compaction is pending.
- **Projects: tiles named by the session.** A tile in the rail and the switcher shows the initials of its session's title (this window's own on this project's tile, else the first titled window of the folder; a one-word title gives its first two letters), not the folder's first letters, so folders like *ai-ide* and *ai-notes* no longer share a tile. With no title yet, or for another computer's bare row, it is the folder's (now also by words: *ai-ide* is AI). The colour still follows the path. The rail's tooltip leads with the title, the folder next.
- **Phone: running tasks and subagents.** The chat header shows the count of running tasks (`⚙ 2`, `✓ 3` when only finished ones are left); a tap opens them as on the desktop: subagents, swarms with their agents, shell tasks and monitors, with status, time and model. **Stop** (asks in place), **Stop all** for a swarm and **To background** work as on the desktop; a subagent opens its conversation read-only and a shell task its output, both updating while they run. A computer without these controls shows the list without them.
- **Two windows no longer lose each other's change** to a shared state file (preferences, sessions, read marks, archived chats): every update is made under a lock.
- **Comments: a comment on a whole picture from the phone no longer gets stuck.** A comment the window refuses no longer sits in the phone's or the page's queue for good.
- **Comments: images alone are enough.** A comment with only pasted images, or (on the computer) a drawing with no words, can be added; before, the window refused it and it was lost.
- **Tabs: Usage, Settings, Remote, Changes and Git log survive a reload.** They come back in their place, the active one active, as file tabs do. In Usage, **Where it went** keeps Tasks or Projects (and **All**) when the period or provider changes.
- **Video edits: reverse a clip.** **Reverse** in the clip panel (also for several clips at once, undoable) plays a video or sound clip's used part backwards, picture and sound, for loops; the edit file says `"reverse": true`. Its fades stay at its ends, trims, cuts and comments keep what plays where, and its waveform and thumbnail are drawn reversed. Photos can't be reversed. The preview plays a reversed copy that ffmpeg makes once per part (at most 1280×720, kept in the project's `.nota-bene/reverse/`, out of git); the clip says *reversing…* until it is ready. Reversing holds the whole part in memory, so a part over about 2 GB of frames is *too long to reverse* and Export refuses it. A reversed clip loses its alpha channel in the export.

## 2.1.0 — 2026-11-18

- **Video edits: the format and a read-only timeline.** A `*.nbcut.json` file (tracks of video, photos and sound; the format is in the guide) opens as a timeline with its tracks, clips and thumbnails, a ruler, zoom and a playhead. Problems in the file and missing sources are listed in the view.
- **Video edits: preview.** The edit plays in a frame above its timeline as the export renders it (stacked video tracks, placement, the sound mix with fades, mute and solo). Scrub on the ruler or the playhead; Space/K play, `,`/`.` step a frame, ↑/↓ jump to clip edges, Home/End. Every track is heard, however many the edit has: a clip at the playhead before the first play (in its fade-in, muted or turned down) no longer leaves its track silent or too quiet until a track is added, and a track that adds nothing (hidden and muted) loads nothing.
- **Video edits: export.** **Export** on the edit's timeline renders it with ffmpeg on the machine into `exports/<name>.mp4` (H.264/AAC at the edit's size and frame rate) or the sound mix alone (`.wav`, `.m4a`), with progress and cancel. Without ffmpeg the editor still works and Export says how to install it.
- **Video edits: editing on the timeline.** Select, move (also between tracks of a kind), trim, split (S), duplicate and delete clips, with snapping to the playhead and clip edges (Alt: none); add, rename, reorder, mute, solo, hide and remove tracks; drag a video, sound or photo from Files onto a track. The selected video clip's frame moves and resizes on the preview, and a clip panel edits its numbers. Undo and redo; every change is saved to the file, an outside change reloads it, and an edit against an older version asks before overwriting.
- **Video edits: Select and Blade tools, multi-select.** The edit bar has **Select** (V) and **Blade** (C); Esc goes back to Select. The Blade cuts the clip under a click at that point, snapped as edges are, and Shift+click cuts every track; a line shows where it will cut. Shift- or ⌘/Ctrl-click adds or removes a clip, and a rectangle dragged on empty space selects every clip it touches. A selection moves together, keeping its times and tracks, or not at all when a clip would overlap; Delete, the nudges and Duplicate act on all of it, and the clip panel sets the shared gain, mute and fades. **+ Video** and **+ Audio** moved to the track column.
- **Video edits: move a clip with what follows it, ripple trim.** Shift+drag on a clip moves it and every later clip on its track together, gaps kept, stopping at the previous clip and at 0; Shift+drag on its end edge trims it and the later clips follow. A Shift-click without a drag still adds or removes the clip, now on release. See [Video edits](https://github.com/iCubeDm/nota-bene-ide/blob/main/docs/guide.md#video-edits-nbcutjson).
- **Video edits: sound and fades on the clips.** Clips with sound draw their waveform. Drag the line across a clip to set its gain (the dB shows while you drag; Shift: fine steps), and the handles at its top corners to fade it in and out. On a video track the fades fade the picture too: from and to black on the lowest track, over what is under it on an upper one, in the preview and the export. An edit written before keeps its meaning for the sound; a video clip's `fadeIn` / `fadeOut` now also fades its picture.
- **Video edits: a level meter and track gain.** The preview's toolbar has a master level meter beside the time: a bar per side in dBFS, the peak held 1.5 s, and a dot that turns red once the mix reaches 0 dBFS and stays so until clicked. A track header shows its gain beside the name; click it to type a value in dB. See [Video edits](https://github.com/iCubeDm/nota-bene-ide/blob/main/docs/guide.md#video-edits-nbcutjson).
- **Video edits: comments on the timeline.** **Comment** (M) in the edit bar comments on the selected clip (at the playhead when it is on the clip, else at its start) or, with nothing selected, on the playhead's moment. The agent gets the edit, the clip, its track, its source file and the time both on the timeline and in that file. Ticks on the clip or the ruler show the note on hover; a tick or the card seeks there and selects the clip. A pending comment follows its clip when it is moved or trimmed; a removed clip's card says so. The phone shows such comments as text.
- **Video edits: the agent's changes highlighted.** When the agent writes an open edit, the timeline reloads it and briefly rings the clips it added or changed, with a dashed outline and its file's name where a removed clip was (in a hidden tab, once you switch to it); your own edits are never highlighted, and reduced motion holds the marks still. The guide has a worked example: ask for a rough cut, then fix it on the timeline or comment a clip or moment (M). See [Video edits](https://github.com/iCubeDm/nota-bene-ide/blob/main/docs/guide.md#video-edits-nbcutjson).
- **Video edits: add files from the tree, a new edit from a selection.** The Files tree picks several files with ⌘-click (Ctrl-click on Windows/Linux) and Shift-click, and a file's right-click menu has Copy path. On videos, sounds and photos it has **Add to** the open edit (the one you looked at last: after the end of the first track of each file's kind, one step of undo) and **New edit from …** (`edit.nbcut.json` beside them at the first video's frame size, the files back to back, opened).
- **Video edits: selection leftovers.** A selection rectangle can start in the track column and on the rows below the tracks too. A group nudge or drag that is refused (a clip would overlap another, or has no track of its kind there) says why in the edit bar. With several video clips selected, the clip panel sets their position, size and opacity together (*mixed* where they differ), as one step of undo.
- **Video edits: a file icon of their own.** A `*.nbcut.json` shows a timeline icon in the Files tree, tabs and pickers instead of the JSON braces.
- **Video edits: tracks grow from the middle.** **+ Video** adds a track above the video tracks and **+ Audio** below the audio ones, so video stacks upward and sound downward.
- **Open projects in a rail on the left.** Every running project is a tile at the window's left edge, in a fixed order by name, with its state dot and badge (**!** when it waits for you, otherwise its unseen replies); a click switches to it, **+** opens a folder. Settings → Defaults → **Projects rail** turns it off for every window of this agent; narrow windows hide it. See [Projects](https://github.com/iCubeDm/nota-bene-ide/blob/main/docs/guide.md#projects-switching-opening-creating).
- **Back after switching projects.** After a switch with the projects rail, the browser's Back (the button or a trackpad swipe) returns to the previous project as before, and its rail switches projects again instead of ignoring every click, as it does after a switch cancelled before the other window opened. The rail and the header's list show the projects as they are now, and the projects menu and the Open folder dialog come back closed.
- **Files between Nota Bene and the computer.** Any file, not only images, can be pasted, dropped or picked in the composer and a comment popup: it is copied into the project's `attachments/` folder (a name clash gets ` (2)`) and its path goes into the message at the caret; a sound or video plays in the feed. Every file in the Files tree drags onto the composer (its path, or those of all picked files) and, in Chrome and Edge, out to Finder or the desktop as a copy. An upload can be cancelled from its chip. A file's menu has **Download** (each picked file), and on the computer the window runs on **Show in Finder** (Explorer on Windows, the folder on Linux) and **Open in default app**, which opens documents and media only. The server refuses both through the phone relay and for helpers.
- **Media markup: a Mask tool.** **Mask** (G) in the markup toolbar outlines an exact area point by point: a click adds a point, a click on the first point, Enter or a double-click closes it, Backspace removes the last point and Esc drops the shape. Closed shapes are filled half-transparent in the mark colour; drag a point to adjust one or drag inside it to move it (Cmd/Ctrl+Z undoes a drag; Alt-click starts a new shape inside one), several per comment. The agent gets every point in pixels and a `mask.png` beside the frame (white inside the shapes, black outside, the frame's size), ready for inpainting. The phone shows these shapes on comments it receives.
- **Fix: Esc while drawing a shape.** Esc during a drag (any tool) now drops only that unfinished shape, with no question; with nothing in progress it leaves markup as before. Leaving markup mid-drag no longer brings the shape's start point back, with a grey shape following the pointer, the next time markup is opened.
- **Dates and times on messages.** Your messages show their time in the header and the agent's replies on hover, with the date when it is not today and the full date and time in a tooltip; a line marks each new day (Today, Yesterday, the date). Loaded history keeps its times now (Claude and Codex); an old record without one shows none. In the UI language.
- **A server restart waits for the agent.** **Restart the server** (the ↻ menu, Restart server · code updated, Settings → Windows) no longer kills a running turn and its subagents: it waits for the agent to finish, and the header shows **Restart pending** with **Restart the server now** (asks first) and **Cancel**. When a restart did cut a turn (Restart now, a crash, a stop mid-turn), the resumed chat says so with **Continue**. ↻ Restart the agent is unchanged.
- **Images and videos in replies on the phone.** A project image or video an agent's reply embeds (`![](design/shot.png)`, `![](media/clip.mp4)`) shows in the phone's feed: an image as a preview (its shape kept, up to 240 px tall, read once per chat; a picture over 8 MB says so and opens full screen on a tap), a video as a tile with a play mark and its name. A tap opens it full screen at once, in the phone's image viewer (zoom, markup, comments) or video player; back returns to the reply. The same in a Markdown file opened on the phone, its paths taken from the file's folder. A missing, outside, too large or unreadable file is a small row saying so; `https:` images show as before.
- **Sounds in replies on the phone.** A project sound an agent's reply embeds as an image (`![](clips/take.mp3)`: mp3, wav, m4a, ogg), shown on the desktop as a player, is a play row on the phone too, with play/pause, the file's name and, once it plays, its position and length (tap or drag the bar to seek). The same goes for a Markdown file opened on the phone, its paths taken from the file's folder as on the desktop. It is read from the window when it starts (up to 64 MB) and plays through the voice messages' player, so one sound plays at a time. A missing, too large or unplayable file says so.
- **The phone keyboard after switching apps.** Leaving the app with the keyboard open and coming back no longer leaves the message line floating mid-screen or the attachment sheet's Send button under the navigation bar: the field gets its focus back with a fresh keyboard.
- **An outdated `/nb` plugin says so.** The window's own update does not update the Claude Code plugin, and Claude Code does not update a third-party marketplace by itself. A window opened by `/nb` from a plugin older than the version it now runs shows **Update the /nb plugin** in the header with the commands (`claude plugin marketplace update nota-bene`, `claude plugin update nota-bene@nota-bene`, then restart Claude Code); **Got it** hides it until the next plugin version. README and guide say how to turn on auto-update for the marketplace.
- **Fix: `/nb` under auto mode.** The skill now pre-approves its own `!` command exactly (`Bash(node "${CLAUDE_SKILL_DIR}/open.mjs" *)`), instead of only by wildcard patterns, which auto mode may drop as too broad. The guide's troubleshooting covers *Shell command permission check failed* from an older plugin.
- **Short tooltips.** A tooltip now only names an icon button and its key or slash command: *Compact context (/compact)*, *Clear context (/clear)*, *Projects (⌥P)*, *Voice message (⌥R)*, *Settings*, the usage meters and the edit's tools among them, in every language. Send, Stop and Attach, tabs, menu rows and text buttons have none, nor does a gesture (a clip's trim edges, the ruler, the playhead), and three long settings hints (projects rail, sounds, audit log) are one sentence. A disabled button still shows its tooltip. On the edit bar, **Select** (V) and **Blade** (C) are an arrow and a razor-blade icon, the active one in the accent colour, and Split, Duplicate and Delete are scissors, copy and trash icons. The header path has a copy icon on hover; file tabs that share a name show enough of their folder to tell them apart.
- **A working project's dot pulses.** In the projects rail and the project list, the state dot of a project whose agent works pulses in the accent colour, as the composer's indicator does.
- **Usage: tokens per 1% per week.** Each weekly column of the tokens-per-1% table is that week's own value (its tokens over its percent), no longer averaged with the later weeks; the 5-hour row is taken from that week's own 5-hour windows (web and phone).
- **Usage: a limit reset mid-window.** When the provider resets a limit before its window ends, the window's percent adds the use before and after the reset, so its tokens per 1% stays right.
- **Numbers in the UI language.** Token counts, file sizes and costs are written as the UI language writes them, the same on the web and the phone: `1.5K`, `2,5 млн`, `250万`, decimal sizes (`0.8 kB`, `314.6 MB`), `1,23 $` in Russian. The All tabs menu tells files with the same name apart as the tab strip does.
- **Faster long chats.** A streamed reply re-renders only the message it changes; reconnecting and the phone no longer replay every streamed token; the header's git status takes one git call instead of several, and the Changes view and Codex's background-terminal check poll less.
- **Long words wrap in messages.** A long word without spaces (a path such as `audio/intro/{a,b,c}.mp3`, a URL) in a message's text, list items, headings and links, in a comment's quote, in a Markdown file's preview, in the error after a finished turn and in a permission request breaks at the column's edge instead of running past it. Tables keep their column widths.
- **Fix: tables of sounds and wide tables in replies.** A table wider than the message scrolls sideways inside it instead of running past its edge; comment marks on its text stay inside it and follow the scroll, and a jump to a comment there scrolls the table to it. A sound player in a narrow place (a table cell, a thin column) keeps its controls on one line, the time included, and drops what no longer fits: first the seek-step chip, then speed; the volume slider takes the room left. The speed and seek-step menus open above everything, so a table no longer cuts them off. Short row labels no longer wrap.
- **Fixes from the pre-release inventory.** Opening a tab no longer waits up to 5 s for `ffmpeg -version` (it is asked in the background; an export still refuses an ffmpeg older than 4.4); Codex and omp are told the real Nota Bene version; the usage and dictation settings refuse an oversized request (413); THIRD-PARTY-NOTICES lists the licenses of every library the package bundles or depends on.
- **The experimental 3D viewer is gone.** `.glb`, `.gltf` and `.blend` files open as any other file, `NOTA_BENE_EXPERIMENTAL_3D` and the Blender conversion (`/model`, `NOTA_BENE_BLENDER`, `cache/blend/`) are removed, and the package no longer ships three.js. A comment made on a 3D view keeps its text and frame. The undocumented `NOTA_BENE_IDLE_COMPACT_MINUTES` is removed too.
- **A new README and a shorter guide.** The README shows what Nota Bene is for, with media of the video editor and voice messages; the guide is concise.

The header and the tab title carry the same badge for the other projects. A project at a drive root (`D:\`) serves its files, `@`-completion hits with backslashes are normalised, and shortcut tips show Ctrl+Enter and Ctrl+V off a Mac.
