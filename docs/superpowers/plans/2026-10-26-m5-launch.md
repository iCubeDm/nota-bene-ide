# M5 Launch & Self-hosting Implementation Plan

**Goal:** The user opens the rebuild with `/nb` from Claude Code, exactly as they open the prototype today; then the prototype is retired. Delivers: a `nota-bene` launcher with a supervised full restart; one window per folder; `new` / `fork`; the user's prototype state carried over; dev mode isolated from the working window; deferred M3/M4 polish that users hit daily.

**Architecture:**
- `bin/nota-bene.mjs` is a small Node supervisor (no dependencies, `node:child_process`): parses arguments, builds `web/dist` when stale, spawns the server child with `NOTA_BENE_SUPERVISED=1`, relaunches it with `--continue` on exit code 75 and after crashes (gives up at 5 crashes in 60 s), and registers the window in `~/.nota-bene/windows.json`.
- The `/nb` skill (`skill/` in the repo, symlinked as `~/.claude/skills/nb` at switch-over) brings up the window already serving the folder, or launches the bin detached on a free port in 4777-4799.

**Spec:** `docs/superpowers/specs/2026-10-24-nota-bene-rebuild-design.md` ("Parity checklist -> Launch & self-hosting (M5)", "restart" R-M4-1). **Reference (read only):** `prototype/ide.sh` (supervisor loop, exit codes, crash guard), `prototype/skill/SKILL.md` and `open.sh` (argument aliases, guards, port probing, `NB:` output contract, last-session check), `prototype/server.mjs` (`--fork` with `forkSession`, `.sessions.json`). Base: branch `m5-launch` from `main`.

## Constraints and rulings

M0-M4 rules hold (trailer `Task: M5-NN`; ports 4790 smoke, 4791-4795 e2e, never 4777-4781 for tests; smoke runs use temp `NOTA_BENE_HOME` and `CLAUDE_JOURNAL_VAULT` and their transcripts go to the Trash afterwards). The live window range stays 4777-4799 like the prototype; during the transition both apps may hold ports there and `/info.root` tells them apart.

Launcher exit codes follow `prototype/ide.sh`: 75 relaunches immediately with `--continue`; 0, 130, 143 exit; anything else is a crash, relaunch after 1 s, give up at 5 crashes within 60 s.

- **R-M5-1.** The plain ↻ keeps restarting the agent (R-M4-1). A full server restart is a second action in the ↻ menu, shown only when `/info.supervised` is true.
- **R-M5-2.** Dev mode never touches the working state: `npm run dev` defaults `NOTA_BENE_HOME` to `~/.nota-bene-dev`, ports 4780 and 5173 as today.
- **R-M5-3.** The prototype is retired, not deleted: `prototype/` stays as an archive and reference. Retiring = the `/nb` symlink points to the rebuild, local root compat symlinks are removed, docs say so. The user's `~/.claude/skills/nb` symlink is switched only after the user confirms in chat.
- **R-M5-4.** Prototype state is imported once and idempotently: `prototype/.sessions.json` folder-to-session entries become `sessions.json` entries unless the rebuild already has one for that folder; `_mode:<port>` combined with `_root:<port>` becomes `prefs.modes[root]` (same rule). A marker `importedPrototype: true` in `prefs.json` prevents a re-run.

## Review focus (each has a test)

1. Two `/nb` calls on one folder at once: exactly one server serves it and the second reports "already open". Port binding is the arbiter (the loser fails to bind or finds the folder registered and exits cleanly) (M5-04).
2. Stale `windows.json` entries (killed process, port reused by another app, a prototype window): every entry is verified with `/info.root` and a live pid, stale ones pruned; a wrong window is never brought to front (M5-02, M5-04).
3. Exit codes and signals: Ctrl-C and SIGTERM stop the child and exit without relaunch; a child killed by a signal is a crash; 75 relaunches with `--continue` on the same port so the browser tab reconnects by itself (M5-02).
4. `--fork` never appends to the source transcript: the window gets a new session id, the terminal's session is untouched (M5-01; real check in the M5-10 smoke).
5. The migration never overwrites newer rebuild state and runs once; a corrupt or missing prototype file is skipped silently (M5-05).

## Contracts

Server launch options (M5-01):
- CLI: `node server/src/main.ts [dir] [--port N] [--resume ID [--fork]] [--new] [--continue] [--fake script] [--allow-origin O]`.
  - Default (no `--resume`/`--new`): resume `lastSession(dir)` only if its transcript `~/.claude/projects/*/<id>.jsonl` still exists (as the prototype's open.sh checks), else a new session. `--continue` is the same as the default. `--new` always starts new.
  - `--resume ID --fork` passes `resume: ID, forkSession: true`; the new id comes from init and only it is saved. `AgentBackend.start` gains `fork?: boolean`; the fake records it and gives the forked session a new id.
- `/info` gains `supervised: process.env.NOTA_BENE_SUPERVISED === '1'`.
- `POST /restart-server`: Origin-checked; 409 when not supervised; otherwise 200, flush, close the agent, `process.exit(75)` after 100 ms.

Launcher and registry (M5-02):
```ts
// windows.ts: ~/.nota-bene/windows.json = { [port]: { root, pid, startedAt } }
registerWindow(port, root, pid)     // atomic, merge
unregisterWindow(port, pid)         // only if the pid matches
liveWindows(probe)                  // verifies via /info + pid alive, prunes stale
```
- `nota-bene [dir] [--port N] [--resume ID [--fork]] [--new] [--detach] [--no-open]`: refuses `$HOME` and `/` with the prototype's message; realpaths `dir`; without `--port` takes the first free port in 4777-4799 by a real bind test (not `nc`); builds `web/dist` (`npm run build -w web`) when missing or older (mtime) than anything under `web/src`, `web/index.html`, `shared/src`; spawns the server with `NOTA_BENE_SUPERVISED=1`, registers after `/info` answers, unregisters on exit; supervisor loop as above, where a relaunch adds `--continue` and drops `--resume`, `--fork`, `--new`; opens `http://127.0.0.1:PORT` on the first start only (`open` on macOS, `xdg-open` elsewhere) unless `--no-open`.
- `--detach` re-spawns itself detached (stdio to `${TMPDIR}/nota-bene-PORT.log`), waits up to 20 s for `/info`, prints the URL and exits 0; on timeout prints the last 15 log lines and exits 1.
- SIGINT/SIGTERM go to the child; after it exits the launcher exits 0 and never relaunches.
- Helpers used by the skill: `--find "$DIR"` prints the port of a live window serving the folder; `--last "$DIR"` prints the last session id if its transcript exists.

Restart menu (M5-03): plain click on the arrow button keeps the agent restart; a chevron opens `restartAgent` ("Restart the agent") and, only when `/info.supervised`, `restartServer` ("Restart the server", tooltip "picks up server code changes; the window reconnects by itself"). The server restart POSTs `/restart-server`, shows `t('restarting')` until the socket reconnects and a `session` event arrives, and toasts `t('restartFail')` with the response text on non-200.

`/nb` skill (M5-04):
- `SKILL.md` is the prototype's, with arguments `[new | fork]`, the same `NB:` contract, `allowed-tools: Bash(*/nb/open.sh *)`.
- `open.sh "<args>" <callerSessionId>`: same aliases as the prototype (`new|новая|новую|заново`, `fork|continue|here|продолжить|продолжи|форк`; unknown prints usage). Guards: inside Nota Bene (`NOTA_BENE_SUPERVISED` or `AI_IDE_SUPERVISED`) prints "already running inside Nota Bene"; `$HOME` and `/` refused.
- Existing window: `bin/nota-bene.mjs --find`, with a fallback probing `/info` roots on 4777-4799 (which also finds prototype windows during the transition); on a hit open that URL and print "already open at ..."; with `fork` print the prototype's "NOT switched" note.
- Otherwise launch: last -> `nota-bene "$DIR" --detach` (the note says resumed or new, via `--last`); `new` -> `--new`; `fork` -> `--resume "$SID" --fork` (SID validated as a UUID). Output: the prototype's lines, with `NB: opened http://127.0.0.1:PORT for DIR (...)` plus the log path.

Migration (M5-05): `importPrototypeState({prototypeSessions}) -> {sessions, modes}` (R-M5-4). Folder keys are realpath'd; entries whose folder is gone are skipped; when several ports map to one folder the highest port wins (deterministic); never overwrites an existing rebuild entry; called once from `main.ts` at start.

Dev isolation (M5-06): `dev` runs with `NOTA_BENE_HOME=${NOTA_BENE_HOME:-$HOME/.nota-bene-dev}` (a tiny node wrapper if needed for portability); the server logs `state: <dir>` at startup; `main.test.ts` checks the state dir comes from the env.

## Deferred polish

Server (M5-07):
- Stray "done 0s" line after a real `/clear` (the CLI sends a `result` after `conversation_reset`): emit that result with `{store:false}`, remembering the `/clear` command's turn; the fake adds the result as the real CLI does.
- A send refused with `busy` during a switch replies to the asking socket only with `{kind:'send-refused', id, reason}` (new ServerEvent, protocol update); never broadcast.
- `backend.history` racing a 20 s timeout during a switch: on timeout report it, continue with an empty replay, do not hold `switching`.
- `listSessionsView` normalises each `cwd` with `realOr` (the picker's "this project" check).
- The stats 5-minute tick skips when no socket is attached.
- Branch blobs serve Range (slice the buffer with `parseRange`) so Safari can seek video from branches.

Web (M5-08):
- `send-refused` restores the draft (text and attachments stay in the local slice until the server accepts; the client keeps the last sent draft until the echo) and toasts `t('sendRefused')`.
- Comment editing (popup add, card edit, delete) is disabled while switching, tooltip `t('switching')`.
- A refused Clear (busy after the dialog opened) shows the same short note as the picker.
- Meter placement matches the prototype's footer: compare a screenshot of the prototype at 1456x816 (port 4790) with the rebuild and move the meters if they differ.
- controls e2e gets an idempotent `afterEach` reset (mode default, comments cleared, open asks denied, switch back to Alpha).
