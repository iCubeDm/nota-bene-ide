# Remote app shell (#88) Implementation Plan

**Goal:** An Android Flutter app that pairs with a host by QR, keeps one end-to-end channel per paired host through the relay, lists each host's windows, and works in a window's chat as an ordinary tab: read, send, answer approvals and questions, stop, compact, switch model and effort, restart the agent, take the window over.

**Approach:** Two Dart packages next to `mobile/protocol` (`nb_protocol`): `mobile/channel` (`nb_channel`, pure Dart: Noise IK, pairing values, relay device admission, stream mux, channel), a port of `server/src/remote/` proved against the same vectors and worked examples, then end to end against the real Go relay and Node connector; and `mobile/app` (`nb_app`, Flutter: storage, lock, pairing, host links, screens). No state library: plain `ChangeNotifier` with `ListenableBuilder`; every platform plugin sits behind a small interface so widget tests run on the host VM.

**Stack:** Dart 3.8+, Flutter 3.47; `cryptography` 2.9 (X25519, ChaCha20-Poly1305, SHA-256, HMAC); `web_socket_channel` 3; `flutter_secure_storage` 11 (Keystore); `local_auth` 3; `mobile_scanner` 7; `flutter_markdown_plus` 1 (maintained fork; `flutter_markdown` is discontinued); `highlight` 0.7; `flutter_math_fork` 0.7; Mermaid drawn to an image by the desktop's own `mermaid` 10.9.8 in an offscreen `webview_flutter` 4 page, shown with `Image.memory`; `flutter_localizations` + ARB.

**Spec:** `docs/superpowers/specs/2026-11-07-remote-prototype-design.md`. Contracts: `server/src/remote/CHANNEL.md`, `relay/PROTOCOL.md`, `shared/src/protocol.ts` (via `mobile/protocol`).

## Constraints

- Android only; hosts macOS and Linux. Relay URLs `wss://…`, or `ws://127.0.0.1|localhost:<port>` for local runs.
- Six UI languages for every string (`en, ru, zh-CN, es, pt-BR, de`, `UI_LANGS`); ARB files, one per language; a test fails when keys differ.
- Look: Darcula tokens from `web/src/theme.css`.
- No homemade cipher or handshake: primitives from `cryptography`; Noise state machine per spec, checked against `server/src/remote/noise-vectors.json`.
- The phone never holds a window key, cookie or token; on `http` streams it sends only `accept`, `content-type`, `range`, `if-none-match`, `if-range`, `if-modified-since`.
- Phone key: long-term X25519 in Keystore-backed storage, never exported or logged. App opens only after biometric or PIN check.
- Host offline: status line with last-seen time; arrived content stays readable; sending disabled, not deferred.
- Ownership: the phone is an ordinary tab (`/ws?tab=<id>`); occupied -> "Work here" sends `{type:'takeover'}`; after 4001 the same overlay takes it back.
- Tests/smoke on ports 4790-4795, temp `NOTA_BENE_HOME`. Neutral fixtures. Commits `gh-88: …`, squash into `remote`.

## Delivery

Two PRs into `remote`: **PR A** = Tasks 1-7 (channel, cross-language proof, skeleton, storage and lock, pairing, host list; usable alone); **PR B** = Tasks 8-11 (window tab, chat, controls, docs).

## Not in #88

Comments (#89), images and video (#90), usage statistics (#91), dictation (#92), session switching, `/clear`, mode switching, shell commands. The chat renders a comment-less feed; the composer sends plain text.

## Review focus

1. Network change or killed socket mid-turn: reconnect with backoff, ws stream reopens with the same tab id (owner role back at once), feed rebuilt from replay with no duplicates.
2. Revoked phone: relay closes 4403 on every attempt; the app shows "not paired with this host any more" and stops retrying.
3. Window restarted (CLOSE 4904): the tab waits until the host stream lists the port again, then reopens; nothing lost until the new replay.
4. Messages larger than the windows (256 KiB stream / 512 KiB connection, split at 65513): credit granted as consumed; message reassembles intact.
5. Approval answered elsewhere while the sheet is open: `permission-done` closes it; a second tap sends nothing.

## Components and contracts

**Noise and pairing** (`mobile/channel/lib/src/noise.dart`, `pairing.dart`): line-by-line ports of `noise.ts` (HKDF over HMAC-SHA256, nonce = 4 zero bytes + u64 LE counter, `MixHash(rs)` pre-message) and the matching parts of `store.ts`/`relayClient.ts`. `generateKeyPair`, `publicOf`, `dh` (all-zero result throws `NoiseError`), `CipherState` (failed decrypt throws and kills it), `Handshake.initiator/responder` with `writeMessage`/`readMessage`/`split`/`handshakeHash`/`remoteStatic`; `prologue = 'nb-e2e-v1'`, `maxMessage = 65535`, `maxPlaintext = 65519`. Pairing: `b64u`, `parsePairUri` (accepts `wss://` and loopback `ws://`; rejects `http://`, other `ws://`, missing `s`, 31-byte secret, `v=2`), `pairTicket`, `pairProof`, `fingerprint`, `deviceHash`, `relayProof` (role `device`). Tests: every vector byte-for-byte; tampered message kills the state; CHANNEL.md and relay/PROTOCOL.md worked examples. The `protocol` CI job also runs these for `mobile/channel`.

**Mux** (`mux.dart`, from `mux.ts`): same constants (`streamWindow`, `connWindow`, `maxChunk = 65513`, `maxStreams = 64`, `maxCollect = 64 MiB`; codes closed 1000, badFrame 4900, unreachable 4902, unknownWindow 4904, tooLarge 4913, tooMany 4929); `Frame` = `Open, Head, Data(fin, binary), End, Close, Credit`; `Mux(send)` opens odd ids from 1 and never accepts `OPEN`; `MuxStream` has `messages`, `head`, `closed`, `send`, `end`, `close`. `messages` reassembles FIN-delimited messages (beyond `maxCollect`: CLOSE 4913); credit is returned when the listener takes a message (half-window rule); queued data dropped on CLOSE still returns credit. Tests: CHANNEL.md frame example, 1 MiB message with credit, sending past the window gives 4900, 65th stream 4929, empty message, both-ways end gives 1000.

**Channel** (`channel.dart`): `Channel.connect({relay, hostPub, key, ticket?, hello, timeout 15 s})` opens `<relay>/v1/device?host=<b64u hostPub>`, answers the challenge with `relayProof`, sends `{t:'hello', key, proof, ticket?}`, waits for `ok`, then Noise message 1 with the JSON payload; message 2 must decode to `{"v":1,"ok":true}`; then one transport message per mux frame; the host stream opens at once. API: `windows` stream of `HostWindow {port, provider, root, title?, session?, model?, busy, supervised}`, `ws(port, path)`, `http(port, method, path, {headers, body})` returning `{status, headers, body}`, `closed` (relay code or 0), `close()`. `ChannelError(relayCode)`: 4403 when refused, the relay code for any close before message 2. Cross-language proof: test-only Node script `server/src/remote/crossHost.ts` (starts `testRelay`, a window via `startServer` with `fakeBackend` serving `notes.md` and a 700 KiB `big.bin`, a `Connector` with temp home; JSON-lines commands `pair`, `revoke`, `restart-relay`, `stop`; replies `ready`, `code`, `paired`, `revoked`, `restarted`), driven by `mobile/channel/test/cross_test.dart` (tag `cross`: pair by QR and list the window, reconnect with saved pairing, GET with Range gives 206, 700 KiB GET byte-equal, ws tab gets replay then hello parsed through `nb_protocol`, relay restart, revoked phone gets 4403) and `crossHost.test.ts` (so Node-side breakage shows in `npm test`). CI adds `actions/setup-go@v5` (`relay/go.mod`).

**App skeleton:** `mobile/app` via `flutter create --org dev.notabene --project-name nb_app --platforms android`, trimmed. `minSdk 24`, applicationId `dev.notabene.remote`, app name "Nota Bene"; manifest `INTERNET`, `CAMERA`, `USE_BIOMETRIC`, `allowBackup="false"`; `MainActivity` extends `FlutterFragmentActivity` (needed by `local_auth`); debug-only network security config allowing cleartext only to `127.0.0.1`, `localhost`, `10.0.2.2`. `ThemeData darcula()` and `NbColors` ThemeExtension with the `theme.css` token names in lowerCamel (+ `syn*`); a test parses the Darcula block of `web/src/theme.css` and compares. `l10n_test` checks equal keys and that ARB locales equal `UI_LANGS` parsed from `shared/src/lang.ts`. Locale: device locale mapped to `UI_LANGS` (`zh` -> `zh-CN`, `pt` -> `pt-BR`), else `en`. System fonts only. CI `mobile` job: `subosito/flutter-action@v2`, analyze (`--fatal-infos`), format check, `flutter test`, `npm run mobile:assets` (copies `mermaid.min.js`, git-ignored), then APK: signed release when secret `ANDROID_KEYSTORE_B64` is present (password `ANDROID_KEYSTORE_PASSWORD`, alias `nota-bene`, read from the environment), else debug; uploaded as artifact for 14 days; keystore and password never reach log or artifact.

**Storage and lock:** `Vault` (`SecureVault` over `flutter_secure_storage`, `MemoryVault`); `Identity.load` (key `nb.identity`, created once); `PairedHost {id = b64u hostPub, relay, label, pairedAt}`; `Hosts` (key `nb.hosts`, JSON; `add`, `forget`, `lastChat` "<hostId> <port> <root>"; a corrupt value reads as empty and is not overwritten until a change); `Authenticator` (`DeviceAuthenticator` with `local_auth`, `biometricOnly: false`, so PIN/pattern works); `LockGate` re-locks after 5+ minutes in the background; a device with no screen lock gets a screen asking to set one and does not open the app.

**Pairing flow:** `PairFlow(ChannelFactory, Identity, Hosts).pair(qr, deviceName)` returns `Paired(host, hostFingerprint, phoneFingerprint)` or `PairFailed(messageKey)` (not a Nota Bene code; expired or used = relay 4403; relay unreachable; host already paired, offer to keep). Device name from `Build.MODEL` via `device_info_plus`, else "Android phone". Scanner stops at the first `nbremote://` code; camera denied shows a message with a settings button. The pairing channel closes after `ok`; the host link opens its own. A confirm screen shows both fingerprints.

**Host links:** `LinkState {connecting, online, offline, unpaired}`; `HostLink` reconnects with backoff x2 (1 s to 30 s, +-20 % jitter, reset after 60 s online), keeps the last windows while offline and `lastSeen`; 4403 -> `unpaired`, no retry until `start()`. `Links` holds one per paired host. Links pause after 10 minutes in the background. `HostsScreen` groups windows by host (state dot, "offline · seen 5 min ago" or "not paired any more" with Forget); `Home` opens `Hosts.lastChat` only when its host is online and still lists that port and root; no hosts gives an empty state with "Pair a host". Relative times localized.

**Window tab and feed:** `Feed.reduce` ports `web/src/store/feed.ts` for replay, user, agent message-start/chunk/message, tool-call (one-line arg rule, cut at 160), tool-update, turn-start/end, cancelled, compacting/compact-*, reset, permission/permission-done, session, resumed; others ignored. Items: `UserItem, AssistantItem, ToolItem, DoneItem, MarkerItem, PermissionItem`. `TabState {connecting, open, occupied, taken, gone, offline}`; `WindowTab` keeps a uuid-v4 tab id across reconnects; `&passive=1` after `occupied` or `taken`; `open` only on `replay`; `takeOver()` as `store.ts:134-146`; CLOSE 4001 -> `taken`, no reconnect; 4904 -> `gone`, reopens when the port is listed again; link offline -> `offline` (feed stays), online -> reopen.

**Chat rendering:** `NbMarkdown` (`flutter_markdown_plus`): fenced code highlighted by `highlight` with `syn*` tokens, scrollable, copy button; `$…$`/`$$…$$` via `flutter_math_fork` (parse error shows the source in `destructive`); mermaid blocks go to `MermaidBlock`. Mermaid is rendered on the phone by the same mermaid.js as the desktop in a hidden `WebViewController` loading `assets/mermaid/render.html` once, offline, navigation elsewhere refused: `render(id, source, theme, scale)` draws with `htmlLabels: false`, paints the SVG on a canvas and returns a PNG data URL or `{error}`; cache by source + theme; tap opens `InteractiveViewer` zoom; a rejected diagram shows mermaid's error line, never the raw source. If a diagram type emits `foreignObject` and taints the canvas, the fix goes in `render.html`, not a source fallback. `e2e/mermaid-mobile.spec.ts` (Playwright Chromium, same engine as Android WebView) renders every mermaid block of `docs/architecture.md` and the specs and plans, dark and light. `ChatScreen`: app bar (folder, title, model pill, state line), feed (user bubbles, assistant Markdown, tool lines collapsed to name + arg, done lines, markers), "Earlier" via `GET /history`, auto-scroll only at the bottom. Script `scripts/mobile-assets.mjs`, `npm run mobile:assets`.

**Composer, approvals, controls:** Composer sends `{type:'send', id, text}`; while busy asks "Send now and interrupt?" and sends `force: true`; Stop sends `interrupt`; `send-refused` keeps the text with a snackbar; disabled with a reason when not `open`. A plain `permission` opens a bottom sheet with the full command in monospace and Allow/Deny; a `permission` with `prompt` (Codex/OMP questions, structured approvals) is a card in the feed sending `response:{choice, values?}` with the web's rules (required fields gate every choice except `deny`, `decline`, `cancel`; labels as `PermissionCard.tsx:12`). Controls menu: Compact (`command compact`, disabled while busy or without `caps.compact`), Model and effort (sheet from `models`, only when `protocol >= 6 && capabilities.models && models.isNotEmpty`), Restart agent (confirm). `OneTabOverlay` for `occupied` and `taken` with "Work here". Settings screen: paired hosts with Forget (local only; host side is `nota-bene remote revoke`), the phone's fingerprint, "Pair a host".

## Rulings to confirm

- No state library (`ChangeNotifier` + `ListenableBuilder`). Cost if wrong: a later move to Riverpod touches every screen.
- App language follows the phone's locale, not the host's `hello.lang` (hosts may disagree). Cost: one setting later.
- Mermaid as an image, drawn on the phone in an offscreen WebView, not on the host (that would need headless Chromium, about 170 MB, and a new route). Cost if wrong: move `render.html` behind a host route; the widget side stays.
- Lock re-arms after 5 minutes in the background; links pause after 10. Cost: a constant.
- The APK is signed in CI with the author's keystore from secrets, so a newer APK installs over the older one and keeps the phone key and pairings. The author creates the keystore and secrets; the agent never handles them.
