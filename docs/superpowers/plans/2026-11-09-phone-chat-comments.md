# Phone chat comments (#144) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On the phone, the user comments chat messages as on the desktop: long-press a message for quick-label emoji and a menu, select a passage and comment it, see commented passages highlighted and numbered, and send them in the desktop's batch.

**Architecture:** Comments already live in the window's set on the host (`WindowTab.comments`, `{type:'comments'}`), and the phone already anchors Markdown files (`comments/anchor.dart`, `renderedText`, `locateSelection`, the mark injection in `files/file_markdown.dart`). This plan points the same machinery at feed items: a chat anchor's source is `{kind:'message', id}`, its text the item's rendered text as the desktop computes it for `[data-item-id]` roots.

**Tech Stack:** Flutter 3.47.9, Dart; Vitest for the web parity fixture; `scripts/protocol/mobileStrings.ts` for web strings.

**Spec:** `docs/superpowers/specs/2026-11-09-phone-ux-design.md` ("Comments in the chat").

## Global Constraints

- The Global Constraints of `docs/superpowers/plans/2026-11-09-phone-layout.md` apply, with `gh-144:` commits.
- Web-owned texts through `webString` (generator), app texts in all six ARB files.
- No protocol change: comments use the existing `Comment`, `TextAnchor`, `AnchorSourceMessage`.
- Branch `gh-144-chat-comments`, cut from `gh-143-window-sheet`, in `/Users/icubedm/Documents/Projects/ai-ide-phone`.
- Scope (my call): commentable items on the phone are user messages and final assistant replies. Tool panels, plans and subagent replies stay desktop-only for now; their comments made on the desktop still show in the strip and send correctly.

## Review Focus

- A reply still streaming (`final_ == false`): no long-press comment actions, as the desktop excludes `stream:*`.
- A comment made on the desktop on a reply the phone has loaded: highlighted on the phone at the same passage.
- The same quote twice in one reply: the anchor's offsets pick the selected one, not the first.
- A reply compacted away or from before "show earlier": its comment stays in the strip, labelled as the desktop does, and sends.
- Long-press on a code block inside a reply, and on a link: the message menu opens; a tap on a link still opens it.
