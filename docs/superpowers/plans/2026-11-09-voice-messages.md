# Voice messages and the phone composer (#163, #164) Implementation Plan

**Goal:** Telegram-like voice messages: the client uploads a WAV, the host stores and transcribes it, the agent gets the text. Every feed shows a voice bubble. Comments carry voice clips. The phone's composer is Telegram's.

**Approach:** Protocol 14 adds `Voice`, `send.voice`, `user.voice`, `Comment.voice` and the stored `voice-text` event. The server stores the WAV in the attachment store, splits it as the phone does today, and transcribes it in the send queue before the hand-over. Clients only record, upload, send and play.

**Spec:** `docs/superpowers/specs/2026-11-09-voice-messages-design.md`.

## Constraints

- Commits `gh-163: ...` (server, web, phone voice) or `gh-164: ...` (phone composer). Three branches: server (`gh-163-voice-server`), web (`gh-163-voice-web`, from server), phone (`gh-164-phone-voice`, from server).
- Tests on ports 4790-4795 with a temporary `NOTA_BENE_HOME`; never `~/.nota-bene` or a running window; no two full suites at once. Worktrees have no `node_modules`: symlink the main checkout's and trash the links after. No new npm/pub packages, no new Android permissions. Never push or stash; `trash`, not `rm`.
- Every string through i18n (web `web/src/i18n`, phone ARB), six languages.

## Decisions and contracts

- Protocol: `Voice`, `VoiceClip`, `VOICE_BARS = 48`, `VOICE_MAX_CLIPS = 10`, `send.voice`/`send.lang`, `user.voice`, `Comment.voice`, `voice-text` event, `PROTOCOL = 14`, `isVoice` exported. A `send` with `voice` and text, images or commentIds is refused; `text: ''` with voice parses. `lang` matches `/^[a-z]{2,3}$/`; `wave` is 48 ints 0..31; `ms` a positive integer <= 602000; `id` 64 hex; a comment takes up to 10 clips; a clip needs `text` (<= 20000 chars). A reused id is refused with no side effects.
- Server parts: `server/src/voice/parts.ts` `splitWav(wav)` (faithful port of `mobile/app/lib/dictation/wav_parts.dart`, parts 30-60 s, one part's PCM in memory at a time), `wave.ts` `waveOf` (48 slice peaks scaled 0..31, zeros for silence, 48 bars even for short audio), `msOf`.
- Store and routes: the attachment store accepts `audio/wav` (`.wav`); `/attach` still images only; image-handoff code ignores audio. `POST /voice` returns `{id, ms, wave}` (415 not WAV, 400 bad WAV, 413 over 20 MiB or 602 s). `GET`/`HEAD /voice/<id>` with Range (206, `accept-ranges`; 416 out of range). `POST /voice/<id>/text?lang=` returns `{text}` (404 unknown, 503 Whisper off). `transcribeVoice(store, id, lang, run)` splits and transcribes one part at a time through the shared Whisper queue (`transcribeQueued` exported from `dictation/routes.ts`), one retry per part. A 10-minute recording stays under the relay's 32 MB body cap.
- Send path: `SendQueue.push` takes `text: string | (() => Promise<string>)`; a function is awaited inside the chain, then the generation is rechecked; a rejection goes to `fail` (`VoiceError` with `why`: `empty`, `off`, `failed`). `session.send` takes `voice`, `lang`; emits `user` with `text: ''` and `voice`, records the id-to-Voice index (JSONL under the state dir, `server/src/voice/index.ts`, lazy; used to enrich historic `user` events on `load()`), pushes the transcription function, which emits `voice-text {id, text}` or `{id, error}` before returning. Order of mixed voice and typed sends is preserved (second transcription starts after the first). A session switch mid-transcription drops it: no hand-over, no stray `voice-text` in the new feed. A failed transcription gives `voice-text {error}` and a failure event; the agent gets nothing.
- Web: reducer in `web/src/store/feed.ts` patches `voiceText`/`voiceError` by id (also from replay); a failed bubble shows Retry (a new `send` with the same voice and a new id) and is hidden once a later user item has the same voice id. `VoiceBubble.tsx`, `player.ts` (one audio at a time, `<audio>` on `/voice/<id>`), transcript fold toggle. Recording: `recorder.ts` (getUserMedia to 16 kHz mono 16-bit WAV, level callback, 10-minute cap), `RecordBar.tsx`, `upload.ts`; Composer mic (click starts a locked recording, Send uploads and dispatches; Esc cancels; hold-and-release sends), `hk_voice` Alt+R (also in fields); no Whisper opens Settings, Dictation; a protocol 13 server gets no mic; denied mic shows a status note. Comment popup gets a mic, clip rows (`ClipRow.tsx`), Save waits while a clip transcribes; `compose.ts` puts clip texts after the typed text, one per line, in order (clips-only comments compose too).
- Phone: Kotlin `nb/play` (`play {path}`, `pause`, `seek {ms}`, `stop`; callbacks `position`, `done`); `lib/voice/player.dart` (one at a time, fetches `/voice/<id>` via `windowHttp`, caches by id), `voice_view.dart` (play, wave with played part, tap/drag seek, length/position); feed gets `voice`, `voiceText`, `voiceError`. Recorder on `nb/record` (`lib/voice/recorder.dart`); `RecordButton({onRecorded(wav, length), enabled, onUnavailable, onState})` with Telegram's gestures (hold 150 ms, 96 px circle with level halo, slide left 96 px cancels, slide up 80 px locks, short tap shows a hint tooltip) and `RecordRow` (blinking dot, `0:03,4` timer, "Slide to cancel", locked: Cancel/Stop then preview with delete, play, wave, Send); cap sends when unlocked, previews when locked. Both reused by composer and comment sheet. Old `lib/dictation/{voice_button,record_bar,host_dictation,wav_parts,dictation}.dart` and tests deleted once unused; `whisper_sheet.dart` kept.
- Phone composer (#164): Telegram layout, a round button (mic when nothing to send, Send when typing; Stop while busy); paperclip moves to the top once text wraps; a recording is uploaded then sent as `send(text: '', voice, lang)`, never with the dialog; an upload failure keeps a local pending bubble with Retry. Comment sheet adds clips; `composeSend` appends clip texts as on the web.

## Review focus

- Phone offline right after release: the message still reaches the agent (upload finished before `send`); a failed upload keeps the bubble local with Retry, never lost silently.
- Two voice and one typed message queued reach the agent in send order.
