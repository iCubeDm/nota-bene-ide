# M1 Comments Implementation Plan

**Goal:** The prototype's review loop, rebuilt on stable anchors. Select a fragment of a reply or of your own message, leave a comment (typed, a quick label, emoji), collect comments in a side panel and send them to the agent as one batch. Pending and sent marks survive reloads, restarts and resumes.

**Architecture:**
- Comments are server state keyed by session id, persisted in `~/.nota-bene/comments/<sessionId>.json`, synced to every window as a full set (`comments` event, not part of the replayed history).
- The web keeps them in a `comments` slice and locates them in the DOM only through `web/src/anchors/` (TextPosition + TextQuote).
- One overlay layer paints the marks; components never hold DOM ranges.

**Stack:** as M0, plus `emojibase-data` 18.0.0 (emoji list, GitHub shortcodes).

**Spec:** `docs/superpowers/specs/2026-10-24-nota-bene-rebuild-design.md` ("Comment anchors", "Parity checklist -> Comments (M1)"). Base: branch `m1-comments` from `m0-foundation`.

M0's constraints and commit convention still hold (task trailer `Task: M1-NN`).

Scope cuts: comments on files wait for file tabs (M3); count badges on tabs and tree rows wait for M2/M3; image references in a batch wait for attachments (M3). The anchor code takes `AnchorSource` of kind `file` from day one, so M3 only adds UI.

## Review focus (each has a test)

1. A comment on a fragment that later re-renders (streaming ends, language switch, reload) highlights the same text or becomes orphaned, never a wrong fragment (M1-05).
2. Two windows on one session: a comment added in one appears in the other; a batch sent from one is marked sent in both (M1-03).
3. Keyboard collisions: Esc closes the `:` picker before the popup; the popup's Cmd+Enter never sends the chat message (M1-11, M1-17).
4. Selection across two items: clipped to the start item, never a broken anchor (M1-09).
5. A session without an id yet: comments stay in memory and are persisted once the id is known, never to `comments/undefined.json` (M1-02, M1-03).

## Contracts

Protocol additions (`shared/src/protocol.ts`):
```ts
type AnchorSource = { kind: 'message'; id: string } | { kind: 'file'; path: string };
type Anchor = { source: AnchorSource; start: number; end: number; quote: string; prefix: string; suffix: string };
type QuickLabelId = 'looks-good'|'clarify'|'verify'|'example'|'overview'|'patterns'|'alternatives'|'no-regression'|'out-of-scope'|'needs-tests';
type Comment = { id; anchor: Anchor; text; label?: QuickLabelId; status: 'pending'|'sent'; createdAt; sentIn? }  // sentIn = id of the carrying user message
// ClientMessage: { type:'comments'; items: Comment[] } (full replacement of the session's set); send gains commentIds?: string[]
// ServerEvent:   { kind:'comments'; items: Comment[] } (full set, never stored in history)
```
Validation rejects `end < start`, unknown labels, and non-`string[]` commentIds.

Server:
- `CommentStore({dir})`: `get(id|null)`, `set(id|null, items)` (persists only for a non-null id, atomic write), `adopt(id)` (moves the in-memory null-session set under the real id), `markSent(id, ids, sentIn)`. A corrupt file reads as `[]`.
- Sync: on attach send `comments` after the replay; a `comments` message gets `store.set` and a broadcast (`store:false`); a `send` with `commentIds` gets `markSent` and a broadcast; session init gets `adopt`; resume loads that id's set. `session.ts` exposes the current id and an "id became known" hook.

Anchors (`web/src/anchors/`):
- `text.ts`: `textOf(root)` (whitespace runs collapsed), `offsetsOf(root, range)` (null if outside root), `rangeFromOffsets(root, start, end)` (null out of bounds); TreeWalker over text nodes with a raw-to-collapsed offset map.
- `resolve.ts`: `CONTEXT = 32`; `makeAnchor(source, text, start, end)`; `resolveAnchor(a, text)`. Rule: if slice `start..end` equals `quote`, done; else score every occurrence of `quote` by common prefix/suffix context, best wins, ties go to the hit nearest the original `start`; else null (orphaned). A property-style test checks the result text always equals `quote`.

Web state:
- `commentsSlice` (a `serverEvent` `comments` replaces items); thunks `addComment`, `editComment`, `removeComment` update locally and send the full set (optimistic, the server echo replaces); selectors `selectPending`, `selectSentFor(messageId)`. `sendMessage` gains optional `commentIds`.
- `composeBatch(general, items, lang, labelOf)`: general text first, then localised `batchHead`, then numbered items: `N. [where]`, quote lines each prefixed `> `, `-> <label emoji+text> <comment>`, and the label instruction if any. `where` is `t('reply', n, time)` or `t('srcMine')`; the store exposes `selectReplyLabel(id)`. No comments: general text unchanged.

Quick labels (`labels.ts`; id, emoji, instruction sent to the agent; `text` is i18n in ru and en):
- looks-good 👍, clarify ❓, needs-tests 🧪: no instruction.
- verify 🔍: "This seems like an assumption. Verify by reading the actual code before proceeding."
- example 🔬: "This is too abstract. Show a before/after, a sample input/output, or a specific scenario so I can see how this actually works."
- overview 🗺️: "Provide a narrative overview of what is being built, why it is being built, and how it will be built. Add this before the implementation details."
- patterns 🧬: "Search the codebase for existing patterns, components, or utilities that already solve this. Reuse what exists rather than introducing a new approach."
- alternatives 🔄: "Propose 2-3 alternative approaches with trade-offs based on the actual codebase."
- no-regression 📉: "Verify that this change will not break existing behavior. Identify what could regress and how to protect against it."
- out-of-scope 🚫: "This is not part of the current task. Remove it and stay focused on what was actually requested."

(Source: Plannotator's built-in labels, with Plannotator-specific paths trimmed from the alternatives instruction.)

Emoji (`emoji.ts`): `searchShortcodes(q, limit?)` (prefix matches first, then substring; GitHub shortcodes), `emojiGroups()`. Data is loaded lazily by dynamic import (`emojibase-data/en/compact.json`, `.../shortcodes/github.json`) to stay out of the main chunk.

## UI behaviour

- `SelectionButton`: on mouseup inside `#items`, the start item (closest `[data-item-id]`) must be a final assistant item or a user item; the range is clipped to it; a non-empty selection shows a floating Comment button which opens the popup with `makeAnchor({kind:'message', id}, textOf(item), ...)`. Streaming blocks never offer it.
- `CommentPopup` (the prototype's `#pop`): one-line quote, textarea, quick-label chips (emoji plus text, `title` = instruction), emoji button. Cmd/Ctrl+Enter adds, Esc or an outside click cancels. A chip adds immediately with `label` and any typed text. After adding, the selection clears and the panel opens.
- `ShortcodePicker` (generic over a textarea ref, the prototype's `@` picker model): `:` plus 2 or more letters at a word start opens up to 8 matches; arrows move, Enter/Tab inserts, Esc closes only the picker; a manual `:code:` is replaced on the closing colon.
- `EmojiMenu`: popover with search (shortcode or name) and grouped grids; a click inserts at the caret and keeps the popup open; the 16 most recent first (localStorage `emoji:recent`).
- `HighlightLayer`: for each comment whose item is in the DOM, `resolveAnchor` then `rangeFromOffsets` then `getClientRects()` merged per line (the prototype's `lineRects`); absolutely positioned boxes, radius 4px, pending `oklch(0.88 0.18 95 / .38)`, sent `oklch(0.75 0.18 280 / .18)`. Repaint rAF-throttled on pane ResizeObserver, feed changes and image load. A click opens the card; orphans are not drawn.
- `CommentCard` (the prototype's `commentCard`): number and `where`, pencil and trash; quote clamped to 3 lines, click jumps to the source; edit via contentEditable `plaintext-only` (check or Cmd+Enter saves, X or Esc reverts, blur saves; buttons use `mousedown preventDefault` so blur does not pre-empt X); label chip; same component in the panel and in a popover over a mark; orphans show `t('orphaned')`.
- `CommentsPanel`: 320px overlay sheet on the right, does not resize the chat, open state in localStorage `panel:comments`; pending cards, empty state `t('emptyComments')`, send button `t('sendN', n)`; header toggle with a pending-count badge (moves into the tab strip in M2).
- Send: composer and panel send `composeBatch(general, pending, ...)` with `commentIds`; Send label shows the count while pending; sending with only comments works; user bubbles list `t('nComments', n)` from `selectSentFor`; sent marks stay dimmed.

## Tests and wrap-up

- Unit tests per task as named above (protocol validation, store, sync with two `ws` clients, anchors, slice, batch text, labels and emoji data, selection, popup, picker, menu, highlight, card, panel, send).
- e2e `e2e/comments.spec.ts`: select, comment, card, send; quick label (batch contains its instruction); `:+1` + Enter inserts 👍 with Esc closing only the picker; edit/delete from the card; reload keeps pending comment and mark; two windows. Run green twice and with `--repeat-each=2`.

## Added during M1: expandable tool lines (M1-19)

Requested by the user on 2026-10-25: the full command and its output were not visible.
- `FeedItem` `tool` gains `input: Record<string, unknown>` and `result?: { text; isError }` (from the `tool_result` with the same `tool_use_id`).
- A click toggles a panel under the line: full input (the `command` for Bash, else the main argument in full plus the rest as pretty JSON) and the output (string or joined text blocks; images become `[image]`; monospace, `max-height: 50vh`, errors red; `t('toolRunning')` until a result arrives).
- `transcriptToEvents` now also emits user messages carrying `tool_result`s as `sdk` user events, so output survives reload and resume; the reducer only attaches them to tool items, no bubbles.
- Long outputs are not truncated in the model; the panel lazily renders the first 20 000 characters then `t('showAll')`.
- Files: `web/src/store/feed.ts`, `web/src/feed/ToolLine.tsx`, `server/src/agent/transcript.ts`, plus tests.
