# M4 Session & Agent Controls Implementation Plan

**Goal:** Full prototype parity for the controls around the chat: session picker over all folders with an in-process switch; session title in the tab and window title; footer meters (context, 5h and week limits, cost); compact and clear; plan card; mode pill with Shift+Tab; prompt suggestions; state favicon; toasts for server errors; restart; background-task line. After M4 only M5 (launch through `/nb`) stands between the user and the switch from the prototype.

**Architecture:**
- One `SessionManager` per server owns the agent and can now replace it in-process. `switch()` and `restart()` close the SDK query and start a new one with resume, possibly in another project folder. The project root becomes mutable server state, read through `manager.info().root` by every route; root-dependent pieces (file routes, sources, completion cache, comment store key) are re-created on a root change.
- New server state goes to every socket as unstored events like `comments`: `stats` and `mode`. `session` grows `title` and `model`.
- The web adds slices `controls`, `stats`, `tasks`. UI-only behaviour (favicon, toasts, suggestions) lives in small hooks.

**Stack:** as M3, no new dependencies. `--chrome` was already done (`extraArgs: {chrome: null}` in `server/src/agent/sdk.ts`).

**Spec:** `docs/superpowers/specs/2026-10-24-nota-bene-rebuild-design.md` ("Parity checklist -> Session & agent controls (M4)", state table `prefs.json`). **Reference:** exact prototype constants, i18n texts and line numbers are in `docs/superpowers/plans/2026-10-25-m4-research.md`. Base: branch `m4-controls` from `main`.

## Constraints and rulings

M0-M3 rules hold (trailer `Task: M4-NN`; ports 4790 smoke, 4791-4794 e2e, never 4777-4781). Manual smoke uses a temp `NOTA_BENE_HOME` and a temp `CLAUDE_JOURNAL_VAULT`.

- **R-M4-1.** The switch is in-process. ↻ restarts the agent in-process (closes the query, resumes the same session). Reloading server code is a dev concern (`node --watch`); M5's launcher adds a supervised full restart. The ↻ tooltip says what it does.
- **R-M4-2.** Permission mode is persisted per project dir in `~/.nota-bene/prefs.json` (spec state table), not per port as in the prototype. Default `'auto'`.
- **R-M4-3.** No native `confirm()`/`alert()`. Confirmations are a shadcn Dialog with Esc and Enter, following the Esc protocol.
- **R-M4-4.** Session picker, compact and clear are disabled while busy; the server also rejects `switch` and `command` while busy (`server-error` `where:'busy'`). ↻ (`restart`) stays available while busy as the escape hatch for a stuck agent: it interrupts first (2 s cap), then resumes the same session (ruled during M4-04).
- **R-M4-5.** Server errors become toasts, deduplicated as xN with a 15 s timeout that pauses on hover. They are no longer feed notices; M3's `tone: 'error'` notice is removed.
- **R14 (from M1).** The client `comments` message carries `sessionId`; the server rejects a mismatch, so a set in flight during a switch cannot land in the wrong session.

Prototype constants kept verbatim: `MODES = ['default','acceptEdits','plan','auto']` (Shift+Tab cycles in that order); meter classes `warn` >= 60 and `hot` >= 85; `fmtK`; stats refresh 1.5 s after start, every 5 min (limits throttled to 1/min), and after every `result`, `conversation_reset`, `compact_boundary`; `getContextUsage` timeout 10 s, usage call 15 s; `cwdOf` reads the first 256 KB and caches results incl. nulls; `listSessions({limit: 300})` dropping entries without a cwd; favicon colours, 700 ms blink, priority wait > work > done > idle; toast dedup key `title\nmsg`, 15 s.

## Review focus (each has a test)

1. A switch with a pending permission card, unsent comments, a comments push in flight (R14), an open file tab of the old root and a playing video: nothing from the old session or root shows or is served (feed, comments, tree, tabs per root, `/file`) (M4-04, M4-16).
2. Two windows on one server: when one switches, compacts or clears, the other follows (replay reset, session event, title, tabs for the new root) (M4-04, M4-16).
3. Mode echo loop: UI optimistic, server echoes, and the CLI can change mode itself (approving a plan drops to `default`, then we restore). It must never oscillate or send `mode` twice per click (M4-02, M4-06).
4. Experimental usage API missing, throwing or changing shape: meters degrade (no limits, cost if known, context alone), never crash or log every tick; `stats` is never in the replay (M4-03).
5. `/clear` with pending comments on chat messages: the old comments stay with the old session, not orphaned in the new one; the panel shows the new (empty) set and the old set returns when reopened from the picker (M4-05, M4-09).

## Contracts

Protocol (`shared`):
```ts
MODES = ['default','acceptEdits','plan','auto']; type Mode
Limit = { utilization: number /* 0..100 */; resets_at: string | null }
Stats = { context: {used,max,pct} | null; limits: {five_hour: Limit|null; seven_day: Limit|null} | null; cost: number | null }
// ServerEvent: { kind:'stats'; stats } and { kind:'mode'; mode } (never stored); 'session' gains title: string|null, model: string|null
// ClientMessage: { type:'mode'; mode } | { type:'command'; name:'compact'|'clear' }
//   | { type:'switch'; id: string|null /* null = new session; /^[0-9a-f-]{36}$/i */; dir } | { type:'restart' }
// 'comments' gains sessionId: string|null (R14); 'permission' gains input?: Record<string, unknown> (plan card passes the plan input back)
```
Bad mode, bad id, relative dir, unknown command and `comments` without `sessionId` are rejected.

Mode (server):
- `readPrefs(): {modes: Record<string, Mode>; lang?}`, `setModePref(dir, mode)` (atomic). `AgentSession.setPermissionMode`; `AgentBackend.start` gains `permissionMode`; `SessionManager.mode()`, `setMode()`.
- Start mode is `prefs.modes[root] ?? 'auto'`. `setMode` calls the SDK, persists, emits `mode`; on failure `server-error` `where:'mode'` and re-emits the current mode. A `system` `init`/`status` with a different `permissionMode` makes the manager follow, persist and emit; the same mode emits nothing. Every new socket gets `mode`.

Stats (`StatsService({session, emit, now?})`): `current()`, `refresh({limits?})` (context always; limits at most 1/min unless forced), `onSdk(m)`, `start()/stop()` (1.5 s first tick, 5 min interval, unref).
- `AgentSession.contextUsage()` maps `totalTokens`, `rawMaxTokens || maxTokens`, `percentage`. `usage()` uses `usage_EXPERIMENTAL...({skipBehaviors:true})` and throws if absent. A failure keeps the previous value.
- `rate_limit_event` with `rateLimitType` `five_hour`/`seven_day` and `utilization != null`: `pct = u <= 1 ? u*100 : u`, `resets_at = resetsAt ? ISO(resetsAt*1000) : null`, merged into `limits` (0.42 gives 42).
- Emitted with `store:false`; missing or throwing API gives at most one `server-error` per process.

Sessions, switch, restart:
- `titleOf` = first non-empty of `customTitle`, `summary`, `firstPrompt` not starting with `/`. `cwdOf(id, projectsDir?)` reads the head 256 KB of `~/.claude/projects/*/<id>.jsonl` with `/"cwd":("(?:[^"\\]|\\.)*")/`, cached incl. null. `listSessionsView({current, root})` returns `{current, root, sessions: [{id,title,at,size,cwd}]}`; `GET /sessions`.
- `AgentBackend` gains `listSessions()` (sdk `listSessions({limit:300})`; fake scripted, e2e needs two sessions) and `sessionInfo(id, dir)` (sdk `getSessionInfo`).
- `SessionManager.switch({id|null, dir})` (rejects while busy), `restart()` = `switch({id: current, dir: root})`, `info()` = `{id, root, title, model}`, `EventHub.reset()`.
- Switch flow: refuse while busy or when `dir` is not an existing absolute directory; close the agent and await its loop; set root to realpath(dir) and persist `lastSession(dir)`; reset the hub (every socket gets an empty replay then the new session's replay); start the new agent with resume and that dir's prefs mode; replay the transcript; emit `session` (id, root, title, model), `mode`, `stats`, `comments` for the new id.
- Root-dependent routes read the root per request; `listFiles`, sources and `cwdOf` caches are invalidated or keyed per root. Title comes from `getSessionInfo` via `titleOf`, refreshed after each `result`, cleared on `conversation_reset`; `model` from `system/init`. R14 rejects a stale `comments` push (`where:'comments'`, "stale session").

Compact and clear (server): `command` broadcasts a `user` event with text `/compact` or `/clear` (visible in the feed) and pushes the plain string with `priority 'next'`. On `conversation_reset`: reset hub history (a reload must not bring the old conversation back), save `new_conversation_id` as current and as `lastSession(root)`, title null, refresh stats, emit `session`, re-send `comments` for the new id (the old id's file stays on disk). `compact_boundary` passes through as an `sdk` event. The fake supports `/compact` (boundary with `pre_tokens`) and `/clear` (reset with a new id). Both rejected while busy.

## Web behaviour

- Mode pill (`controls` state `{mode, modeBeforePlan, restoreAfterPlan}`, `pickMode` thunk optimistic then send, `mode` event sets it). Plan restore: entering `plan` from X records `modeBeforePlan = X`; approving the plan card sets `restoreAfterPlan = modeBeforePlan`; on the next echo of a non-plan mode that differs from it, `pickMode(restoreAfterPlan)` runs once and the field clears. Pill coloured per mode with a menu above (label plus description, current marked); Shift+Tab in the composer (not while composing, no picker open) cycles `MODES`. i18n `modeTip`, `mode_<m>`, `mode_<m>_desc` from the prototype.
- Plan card: a permission with `toolName === 'ExitPlanMode' && input.plan` renders `PlanCard` (plan through `Markdown` with `final`), root `data-item-id="plan:<permissionId>"`, so comments anchor to `{kind:'message', id:'plan:<id>'}` and `whereOf` shows `t('mode_plan')`. Buttons `approvePlan(mode label)` (calls `answerPermission(id, true, input)` and sets `restoreAfterPlan`) and `keepPlanning`; an answered card stays and shows the answer.
- Meters: context, 5h, week; bar 44x4 px with `Math.round(pct)%`, `warn` at 60, `hot` at 85; tooltips `ctxTip(fmtK(used), fmtK(max))`, `h5Tip`/`weekTip` with `resets(at)` in the UI locale; cost `$x.xx` only when there are no limits; null stats render nothing; re-render on language switch.
- Compact and clear: `conversation_reset` clears feed items; `compact_boundary` adds a done line (`compacted(fmtK(pre))`, `cleared(time)`); comments slice resets on a session change; the suggestion clears. `ConfirmDialog({title, body, confirm, onConfirm, onCancel})`: Enter confirms, Esc cancels with preventDefault; clear asks (`clearQ`), compact does not; both disabled while busy; the picker reuses the dialog.
- Session picker: fetches `/sessions`, groups this project first (header marked) then other folders in first-appearance order, first item `newHere`; item shows title or `untitled` and `id8 · ago · size`; the current session is `openNow` and inert; autofocused filter matches title + cwd, keeps `newHere`, hides empty groups. Picking opens ConfirmDialog (`openQ`/`newQ` + `moveQ(dir)` if the folder differs + `switchWarn` rewritten for the in-process switch), sends `switch`, header shows `t('switching')` until the new `session` event. Re-root: a `session` event with a new root restores that root's tabs and tree state and drops the old root's file tabs (media stops via onClose). This resolves M3-05's re-root carry: "restore once per root" becomes "restore on every root change, replacing, not merging". Disabled while busy.
- Prompt suggestions (`promptSuggestions: true` in `sdk.ts`): an `sdk` `prompt_suggestion` sets `suggestion`; any `user` event (replay included), `conversation_reset` or session change clears it. Shown as placeholder only when the field is empty and the agent idle, with a `Tab` badge; plain Tab fills the field and must not steal Tab from an open picker.
- Title and favicon: document title `${title ? title + ' · ' : ''}${project} · Nota Bene`; chat tab label is the title or `t('chat')`, tooltip `title ?? chatTip`; header shows `model · id8`. `useFavicon()` draws the prototype's SVG (circle and NB paths) as a data URL on `link[rel=icon]`. Priority: `wait` while an unanswered permission exists; else `work` while busy, blinking every 700 ms between `#f0761f` and `#8b6cf2`; else `done` (`#22b45a`) when a live `result` arrived while the page was hidden/unfocused (cleared on focus/visibility); else `idle` (`#8b6cf2`). Redrawn only on state change.
- Toasts: `server-error` gives `toast(t('serverError', where), message)`; duplicates increment xN and restart the 15 s timer; hover pauses; close button; top-right below the header, 380 px wide, `<pre>` capped at 160 px; client-side failures (e.g. `/tree`) use the same `toast`. ↻ is disabled only while a switch is running, sends `restart`, header shows `t('restarting')` until the next `session` event; tooltip explains R-M4-1.
- Background-task line (the prototype's `onTask`/`renderTasks`): `task_started` adds an entry (skipped when `ambient || skip_transcript`; `desc` from `description`, then `subagent_type`, `task_type`, `'task'`); `task_progress` updates `tokens`, `tool`, `summary`; `task_updated` with a status other than running/pending/paused removes it, otherwise updates `desc`; `task_notification` removes it; `replay` clears first. Row: gear + desc and `time · fmtK(tokens) tok · tool` (time `Ns` under 60 s else `m:ss`), tooltip is the summary. A 1 s tick runs only while a task is live. Sits above the composer; M2 replaces it later.
- Carried polish (M4-15, from the M1 review): an interrupted reply keeps a per-run `stream:N` id and the Comment button does not appear on `stream:` roots; the CommentCard popover re-clamps to the viewport while editing (ResizeObserver); a mouseup inside the comment popup must not re-show the comment button (`SelectionButton` `onUp` returns for targets inside `[role="dialog"]`; plausible but unverified in the M1 review, verify in Chrome).
