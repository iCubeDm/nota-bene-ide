# Host connector and pairing (`nota-bene remote`) Implementation Plan

**Goal:** A long-running `nota-bene remote` process on the host that keeps one outgoing connection to the relay, pairs phones by QR code, runs an end-to-end Noise channel with each paired phone, and proxies the windows' `/ws` and HTTP routes through multiplexed streams inside that channel.

**Approach:** Code in `server/src/remote/`. The connector reads the window registries of all three providers, proves each window with that provider's token (`/hello`, then the helper bearer) and proxies streams to it on 127.0.0.1. Phone-host traffic is Noise_IK_25519_ChaChaPoly_SHA256 (phone = initiator, host static key pinned from the QR), implemented per the Noise spec on Node's built-in `crypto` and checked against the official vectors. Inside the channel a small mux with HTTP/2-style per-stream and per-connection credit carries the streams. `pair`, `devices`, `revoke` talk to the running connector over a Unix socket.

**Stack:** Node >=22 (`node:crypto`, `node:net`), `ws` 8.22.0, `uqr` 0.1.3 (terminal QR, MIT, no deps), Vitest, the Go relay in `relay/` for integration tests.

**Spec:** `docs/superpowers/specs/2026-11-07-remote-prototype-design.md`; relay contract `relay/PROTOCOL.md`.

## Constraints

- Only built-in `crypto` primitives; no native modules. `uqr` goes into `server/package.json` at an exact version and stays external in `scripts/build-package.mjs`.
- Servers keep listening on 127.0.0.1 only; the connector opens no TCP listener. Its only listener is the Unix socket `<stateBase>/remote/control.sock` (700 folder, socket mode 600).
- Window credentials never leave the host: the phone never receives a token, bearer, cookie or key.
- Secret files (`host.key`, `devices.json`): mode 600, tmp + rename, read with the `readSecret` checks of `server/src/auth.ts` (no symlink, regular file, own uid, no group/other bits).
- The relay sees only ciphertext, routing ids, device hashes and the ticket; never the pairing secret.
- Tests: temp `NOTA_BENE_HOME`, in-process window servers with `port: 0`, nothing on 4777-4789. Neutral fixtures (`relay.example.com`). CLI output English; no web UI strings change.
- Branch `gh-87-connector`, PR into `remote`; commits and title match `^gh-87: .`.

## Review focus

1. Window restart while a phone has streams open (new nonce, old bearer invalid): HTTP re-proves and retries once; a WS stream closes 4904 so the app reopens it.
2. A phone stops reading mid-download: the host stops reading the window once the phone's credit is used up, never exceeds the connection window in flight, other phones keep streaming.
3. Relay drops or laptop sleeps: reconnect with backoff and re-send the device list; 4409 or 4402 stop with a clear message, not a loop.
4. `pair` run twice or Ctrl-C: first code cancelled and the relay's ticket cleared; a stale QR fails.
5. Revoking a phone mid-transfer: its channel is torn down at once, not when the relay's close arrives up to 10 s later.

## Contracts

**Noise** (`noise.ts`, `noise-vectors.json`, `CHANNEL.md` "Handshake"). `KeyPair = {pub, priv}` raw 32-byte X25519; `generateKeyPair`, `publicOf`, `dh` (all-zero result throws); `Handshake.initiator({s, rs, prologue, e?})`, `.responder`, `writeMessage`, `readMessage` (bad tag throws `NoiseError`), `remoteStatic`, `handshakeHash`, `split()`; `CipherState.encrypt/decrypt` (failed decrypt kills the state); `MAX_MESSAGE = 65535`, `MAX_PLAINTEXT = 65535 - 16`; `PROLOGUE = 'nb-e2e-v1'`. Per Noise rev 34, IK pattern: `h` starts as the 32-byte protocol name, `MixHash(prologue)` then `MixHash(rs)`; HKDF over HMAC-SHA256; ChaCha20-Poly1305 with nonce = 4 zero bytes + u64 LE counter, AD = `h` in the handshake; plain `EncryptAndHash` before the first MixKey; raw keys wrapped in fixed PKCS8/SPKI DER prefixes for `crypto.diffieHellman`. Vector file holds only the `Noise_IK_25519_ChaChaPoly_SHA256` entries copied unchanged from the cacophony vectors (or snow's if licence forbids), with a `"source"` field (URL, commit, licence). Tests: every vector byte-for-byte (and at least one entry exists), round trip, flipped bit kills the state, wrong pinned key, low-order key, oversized plaintext. The Dart side must pass the same vectors in CI (#88).

**Store** (`store.ts`; `auth.ts` gains `readPrivateFile(file, valid, what)` and `writePrivateFile`, with `readSecret` a thin wrapper). `remoteDir()` (700), `hostKey()` (`remote/host.key`, base64url private key, created once), `b64u`/`fromB64u`, `hostId = b64u(pub)`, `deviceHash = b64u(sha256(pub))`, `fingerprint` (first 10 bytes of SHA-256 in lowercase base32, groups of 4 joined by `-`), `Device {id, pub, name?, addedAt}` (id = first 4 fingerprint characters, lengthened on collision), `readDevices`/`addDevice` (idempotent)/`removeDevice(idOrPrefix)` (ambiguous prefix throws naming matches) in `remote/devices.json` `{v:1, devices}`, `readConfig`/`writeConfig` (`remote/config.json`, `relay` must be `wss://` or loopback `ws://`). Derivations: `pairTicket = HMAC-SHA256(secret, "nb-relay-ticket-v1")`; `pairProof = HMAC-SHA256(secret, "nb-pair-v1" || phonePub)`. QR URI `nbremote://pair?v=1&r=<encoded relay>&h=<hostId>&s=<b64u secret>` with `pairUri`/`parsePairUri`. `CHANNEL.md` "Pairing" holds a worked example (secret bytes 0x41..0x60 and the device key of `relay/PROTOCOL.md`), computed by code.

**Mux** (`mux.ts`, `CHANNEL.md` "Streams"). Frame (plaintext of one Noise transport message): `type u8 | stream u32 BE | flags u8 | body`. Types: `OPEN=1` (JSON), `HEAD=2` (JSON), `DATA=3` (flags bit0 `FIN` ends a message, bit1 `BIN` binary WS message), `END=4` (half-close), `CLOSE=5` (`{code, reason?}`, both ways), `CREDIT=6` (u32 BE; stream 0 = connection). `STREAM_WINDOW = 256 KiB`, `CONN_WINDOW = 512 KiB`, `MAX_CHUNK = 65535 - 16 - 6`, `MAX_STREAMS = 64`. `Mux({send, onOpen})` with `receive`, `open` (phone uses odd ids; host never opens), `close`; `Stream` events `head`, `message(data, binary)` (reassembled to `FIN`), `end`, `close`, `drain`; `write` chunks, queues beyond credit and returns false while queued; credit is granted back once half a window is consumed after a `message` handler returns. DATA beyond credit is a protocol error: CLOSE 4900 for all streams. Codes: 4900 bad frame or credit violation, 4902 window unreachable, 4904 window unknown or gone, 4929 too many streams; WS streams pass the window's own close code through.

**Relay client** (`relayClient.ts`, `testRelay.ts` builds and spawns the Go relay on a free port; CI job `test` gains `actions/setup-go@v5` from `relay/go.mod`; a missing `go` is a failure, not a skip). `relayProof(role, priv, eph, nonce) = HMAC-SHA256(dh(priv, eph), "nb-relay-v1 <role>" || nonce)`. `RelayClient({url, key, devices(), ticket(), backoff?})` with `start`, `stop`, `setDevices`, `setTicket`, `closeConn`, `send`; events `online`, `offline(code)`, `open(conn, device)`, `gone`, `frame`, `fatal`. Reconnect: exponential backoff 1 s to 30 s, +-20 % jitter, reset after 60 s online. Codes 4401, 4402, 4413 are `fatal` naming the cause, no retry; 4409 is `fatal('another nota-bene remote with this host key is connected')`; everything else (1001, 1006, 4408, 4429) retries. Each (re)connect hello carries current devices and ticket; after `offline` every conn is `gone`.

**Discovery** (`discover.ts`; `readWindows(stateDirOverride?)` in `windows.ts` and an optional `token` on `proveListener`/`verifiedBearer`, behavior unchanged without). `HostWindow {port, provider, root, bearer, nonce}`; `Windows({pollMs 3000, fetchFn})` with `list`, `get`, `reprove(port)` (fresh `/hello`, drops the window on failure), event `change`. A provider with no `token` file is skipped (the connector never creates tokens); a token with bad permissions is an `error` event once per poll. Registry entries are hints: a window is listed only after proof with its provider's token; the connector never unregisters entries. `windowInfo` does `GET /info` with the bearer and `Host: 127.0.0.1:<port>`.

**Device channel** (`device.ts`, `testPhone.ts` = scripted phone, the reference for the Dart app; `CHANNEL.md` "Payloads", "Stream kinds"). Handshake payloads: message 1 `{v:1, name?, pair?: <b64u proof>}`; message 2 `{v:1, ok:true}`. A phone not in `devices.json` whose `pair` proof does not match the in-flight pairing gets no message 2 and the conn is dropped. OPEN bodies:
- `{kind:'host'}`: host sends `{t:'windows', windows:[{port, provider, root, title?, session?, model?, busy?, supervised?}]}` on open and on change (`/info` polled every 5 s only while a host stream is open).
- `{kind:'ws', port, path}`: `path` must start with `/ws`; proxied to `ws://127.0.0.1:<port><path>` with `Authorization` bearer, `Host`, no `Origin`; text/binary kind and the window's close code pass through.
- `{kind:'http', port, method, path, headers?}`: methods GET/HEAD/POST/PUT/PATCH/DELETE; body = DATA until END; response = `HEAD {status, headers}`, DATA, END. Forwarded request headers only `accept`, `content-type`, `range`, `if-none-match`, `if-range`, `if-modified-since`; added `Authorization`, `Host`, and `Origin: http://127.0.0.1:<port>` for non-GET/HEAD. CLOSE 4900 for a path not starting with `/`, starting with `//`, or under `/control/`. `set-cookie` dropped from responses. A 401 triggers `reprove(port)` once and a repeat (only for no body or a fully buffered body up to 1 MiB).
- Unknown port: CLOSE 4904. The window is read only as fast as the stream's credit allows.

**Connector, control socket, CLI** (`connector.ts`, `control.ts`, `cli.ts`; `bin/nota-bene.mjs` dispatches `remote` before `parseArgs` and lists it in `USAGE`). `Connector({relay, windows?, pairTtlMs 300000})`: `start` throws `'nota-bene remote is already running'` when `control.sock` answers; owns the `RelayClient`, one `DeviceChannel` per relay conn, the in-flight pairing. Pairing: `startPairing()` cancels any previous one; secret in memory only; relay ticket while in flight; consumed by the first valid proof (device added, relay list updated, ticket cleared); later proofs refused and emitted as `pair-refused(fingerprint)`; expiry or cancel clears the ticket. `revoke(id)` removes the device, sends the new list to the relay, sends `close{conn}` for every live conn of that key and tears those channels down immediately. Control requests (newline JSON): `status` -> `{online, relay, hostFingerprint, windows, devices:[{id, name?, fingerprint, online}]}`; `devices`; `revoke {id}` -> `{ok, device?, error?}`; `pair` -> stream of `{t:'code', uri, hostFingerprint, expiresAt}` then `paired`, `expired` or `cancelled`; `refused` events go to attached pair clients and stderr; closing a pair client cancels its pairing. CLI: `nota-bene remote [--relay URL]` foreground (saves `--relay`; none saved or given prints how to set one, exit 2; prints fingerprint and online/offline transitions, never content); `remote pair` prints the QR (`uqr` `renderUnicodeCompact`), URI, host fingerprint and waits (paired exit 0, expired exit 1, Ctrl-C cancels); `remote devices` prints `id name fingerprint online`; `remote revoke <id>` exit 1 on error. Non-foreground commands exit 1 with "nota-bene remote is not running" when the socket does not answer.

## Tests

Per task, against real relay and in-process windows: window discovery across claude and codex with proof (an entry answering another token's proof is not listed; no omp token gives no error); device channel (listed phone handshakes; unlisted without proof dropped; pairing proof adds once; host stream lists windows; ws stream gets the first server event and a takeover makes the first tab close 4001; HTTP `/info`, Range file 206, POST with Origin rule, `/control/` and `//evil` closed 4900; restart with new nonce still answers 200; a phone granting no credit gets at most `CONN_WINDOW` while a second phone downloads); connector (pair through the relay, pairing twice cancels the first, closing a pair client clears the ticket, expiry at 500 ms, revoke stops a large download within 500 ms and the next connection gets 4403, second start throws, CLI not-running message, `bin` dispatch reaches `remote`). End to end (`e2e.test.ts`): host stream, ws, `GET /info`, Range, relay restart and phone reconnect, and neither the connector's stderr nor the relay's output contain the file's bytes or the pairing secret.
